## 1. 파일 세트 (국내 글 하나 = 4개)
| 파일 | 내용 |
|---|---|
| `_drafts/<slug>.md` | 네이버판 |
| `automation/variants/<slug>.tistory.md` | 티스토리판 (제목·도입·소제목·문장 모두 새로, 유사도 0.35 이하, 같은 문장 0개) |
| `automation/claims/<slug>.yml` | 두 판의 모든 숫자·날짜·이름 근거 |
| `assets/cards/<slug>-*.png` | `make_cards.py`로 만든 카드 |

해외 글은 `automation/global/drafts/us-<slug>.md` + `automation/claims/us-<slug>.yml` + 카드 (한 판만).

slug 규칙: 영문 소문자-하이픈. 방송 맛집 `<프로그램>-<YYYYMMDD>` (`saengsaeng-info-20261021`, `saengbangsong-today-…`, `hometown-6pm-…`, `master-life-…`), 주간 청약 `subscription-week-<그 주 월요일>`, 그 밖에는 주제-연도.

## 2. front matter (순서도 이대로)
```yaml
---
title: "…"                 # 국내 40~60자 · 핵심 키워드를 앞에 · 날짜/회차 넣기 · 확정 전이면 "(확정 아님)"
description: "…"           # 80~150자 · 무엇을 정리했는지 한 문장 + 핵심 숫자
category: 방송정보          # 정부혜택/청약/세금/노동·급여/부동산/방송정보/이슈/생활/문화·행사
info_as_of: 2026-10-21
deadline: 2026-10-28       # 마감 있는 글만
trend: "…" 또는 cycle: …   # 레이더 키워드 / 캘린더 cycle
publish: now               # 방송정보·이슈·Recalls·급상승으로 쓴 글
channel: [naver, tistory]  # 네이버판에만
tags: [...]                # 네이버 8~15개, 티스토리 5~8개 · 띄어쓰기 없이
cards: {...}               # 3절
sources:                   # 글 끝 '출처' 목록으로 자동 출력 — 본문에 출처 표시는 쓰지 않는다
  - title: "매체 — 기사 제목 (2026.10.21)"
    url: https://...
---
```
해외는 `lang: en`, `labels`, `permalink`(영문 슬러그) 추가, `channel`·`tags` 대신 `labels`.

## 3. 카드 이미지 (검정·흰색·하늘색 #7cc8ff 만)
`make_cards.py`가 front matter `cards`로 그린다. 디자인(안내 표지판 스타일, IBM Plex Sans KR, 위 10px 하늘색 띠, 하늘색은 면으로만)은 바꾸지 않는다.
- **네이버판**: `summary` 카드 1장 필수(도입 바로 아래) + 필요하면 `table` 1장(표 바로 아래).
- **티스토리판**: `t-`로 시작하는 카드 1장(`t-menu`, `t-days`, `t-where` …), 도입 바로 아래. 네이버판 카드와 내용·구성이 달라야 한다.
- 타입: `summary`(kicker · title · big · lines 3줄), `table`(kicker · title · head · rows · note), `steps`.
- kicker: "카테고리 · 프로그램/기관 (날짜)" 형식. 확정 전이면 "확정 아님", 예보면 "○일 예보 기준 · 바뀔 수 있음".
- big: 한눈에 들어오는 한 덩어리(날짜·금액·건수·메뉴 이름).
- 카드에도 "○○ 보도 기준", "블로그 후기 기준" 같은 출처 표시를 넣지 않는다.
- 본문 삽입: `![<무엇> 요약 카드](/assets/cards/<slug>-summary.png)` — alt 는 한국어 설명.

## 4. 본문 레이아웃 (국내)
1. **도입 2~3문장**: 공감 한 줄 + 무엇을 정리했는지 + 이모지 1개. 날짜는 "오늘(10월 21일)"처럼 절대 날짜를 같이.
2. **요약 카드 이미지**.
3. **소제목(##) 3~6개**: 이모지 없음, 질문형은 절반 이하. 방송 맛집은 "코너명: 내용" (`## 결정적 한 수: 청주 시래기장어탕`).
4. 소제목마다 1~3문장 문단 1~3개. 한 문단 = 한 생각. 60자 넘는 문장은 둘로 쪼갠다.
5. 표는 3행 이상일 때만, 카드와 같은 내용이면 둘 중 하나만.
6. **가게·장소**: 이름이 확인된 곳만 지도 링크 한 줄 — 네이버판 `[📍 네이버 지도에서 <이름> 보기](map.naver.com…)`, 티스토리판 `[📍 카카오맵 · <이름>](map.kakao.com…)`. `map_link.py "<지역> <이름>"`.
7. 마무리 소제목(`## 가기 전에` / `## 신청 전에 챙길 것` / `## 정리하면`) — 전화 확인, 공고문 확인, 바뀔 수 있음 같은 실용 안내.
8. **끝인사 한 줄** (고정 틀): `다들 ~하시구! 오늘도 좋은 하루 보내세요~ㅎㅎ` (청약: "다들 청약 꼭 당첨 되시구!", 맛집: "다들 맛있는 저녁 보내시구!", 안전: "모두 안전한 주말 보내시구!").

## 5. 말투 (국내)
- 친근한 블로거: "~했답니다", "~래요/~대요", "정리해 봤어요~", 물결(~)·느낌표, 웃음 이모지는 문장 끝에만(글당 2~4개).
- "~답니다"는 글당 4회 이하. 문장 길이를 섞는다(짧은 문장 + 긴 문장).
- **쓰지 않는 것**: 검증 과정 설명("확인하지 못해…", "두 기사 모두…", "○○는 '인천'까지만…"), 출처 표시("○○ 보도 기준", "블로그 후기 기준", "○○ 보도로는", "○○ 보도에 따르면"), 지어낸 경험, 맛 평가 단정, 매체 이름을 근거로 드는 문장.
- 확인 못 한 가게는 설명 없이 지역·메뉴만 쓰거나 뺀다. 매체마다 숫자가 다르면 매체 이름 없이 범위로 쓴다("약 280~320㎞").
- 확정 전 정책은 "추진 중·예정·확정 아님"을 제목·카드·본문에 쓴다.

## 6. 티스토리판 차별화
- 제목: 다른 검색 의도로 (네이버 "○○ 10월 21일 맛집: A·B 위치" ↔ 티스토리 "A 어디? ○○ 10월 21일 …").
- 구성: 네이버가 단체/항목별이면 티스토리는 요일별·사는 곳/먹는 곳·질문형 등 다른 축으로.
- 도입·소제목·문장 전부 새로. 같은 말투·같은 끝인사 틀.

## 7. 대기함·발행
- `build_outbox.py`: 카테고리 방송정보·이슈·Recalls 또는 `publish: now` → "즉시 발행"으로 맨 위, 나머지는 추천 시각(90분 간격, 7~23시).
- 지도 링크가 있는 글은 카드에 "에디터 [장소] 버튼으로 ○○ 첨부" 안내가 자동으로 뜬다(리뷰 사진 대신).
- 붙여넣기 본문은 `readable_paragraphs`가 문장마다 줄바꿈, 2문장씩 문단을 자동 처리한다(원고는 1~3문장 문단으로 쓴다).
- 이미지는 대기함 HTML 크기(16MB 한도) 때문에 미리보기와 복사 버튼이 같은 데이터를 쓴다.

## 8. 해외(영어) 형식
- 제목 `<Topic> 2026: <the answer>` 꼴, description 150자 이내, H2 4~6개, 마지막 `## The bottom line`.
- 문단 1~3문장, 리스트·체크리스트 적극, 날짜는 AP 스타일(Nov. 11).
- 한 매체만 쓴 세부는 Recalls·이슈에선 빼고(교차 필수), 나머지는 "according to ○○" 정도만.
- 카드: summary 1장 + table 1장, 하단 표기 "Semter"(블로그 이름 확정 전).
